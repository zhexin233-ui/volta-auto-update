# 实施约束总结

本文档记录了 volta-tools-auto-updater 项目的所有明确约束条件，消除了所有决策点，确保实施阶段可以进行纯粹的机械执行。

## 1. 技术栈约束

### 1.1 脚本语言
- **约束：** MUST 使用 Bash Shell 脚本
- **理由：** macOS 默认包含 Bash，无需额外依赖
- **Shebang：** `#!/bin/bash`

### 1.2 依赖工具
- **必需：** volta（运行时检查）
- **必需：** curl（假设 macOS 默认包含）
- **不需要：** jq, Python, Node.js

## 2. JSON 解析约束

### 2.1 解析策略
- **约束：** MUST 使用 grep + sed 简单模式
- **实现：** `grep '"version"' | sed 's/.*"version"[[:space:]]*:[[:space:]]*"\([^"]*\)".*/\1/'`
- **假设：** version 字段在单行内，无转义引号

### 2.2 错误处理
- **curl 失败：** 返回状态 `NETWORK_ERROR`
- **grep 无匹配：** 返回状态 `PARSE_ERROR`

## 3. 版本比较约束

### 3.1 比较算法
- **约束：** MUST 使用简单字符串不等比较
- **实现：** `if [ "$current" != "$latest" ]; then update; fi`
- **不使用：** 语义化版本排序（sort -V）

### 3.2 边界情况
- **current == latest：** 标记为"最新"，跳过更新
- **current != latest：** 标记为"需要更新"，执行更新
- **current > latest：** 仍然尝试更新（用户可能在使用预发布版本）

## 4. 网络请求约束

### 4.1 curl 命令参数
- **约束：** MUST 使用以下参数
  ```bash
  curl -fsSL --connect-timeout 5 --max-time 10 --retry 2 --retry-delay 1
  ```
- **参数说明：**
  * `-f`：HTTP 错误时失败
  * `-s`：静默模式
  * `-S`：显示错误
  * `-L`：跟随重定向
  * `--connect-timeout 5`：连接超时 5 秒
  * `--max-time 10`：总超时 10 秒
  * `--retry 2`：失败后重试 2 次
  * `--retry-delay 1`：重试间隔 1 秒

### 4.2 URL 格式
- **约束：** `https://registry.npmjs.org/<package>/latest`
- **Scoped 包：** 使用 `@scope/name` 格式，无需 URL 编码

### 4.3 网络调用边界
- **约束：** 总调用次数 ≤ 3 × |packages| = 9（每个包最多 3 次尝试）

## 5. Volta 输出解析约束

### 5.1 解析策略
- **约束：** MUST 使用精确包名匹配
- **实现：** `grep '^package @openai/codex@' | sed 's/.*@\([0-9.]\+\).*/\1/'`
- **避免：** 子串误匹配（如 tool 匹配到 toolkit）

### 5.2 错误状态
- **grep 无匹配：** 返回 `NOT_INSTALLED`
- **sed 解析失败：** 返回 `UNKNOWN`

## 6. 输出样式约束

### 6.1 输出语言
- **约束：** 所有输出使用中文

### 6.2 Emoji 使用
- **约束：** MUST 使用以下 emoji 标记状态
  * ✓ - 成功
  * ✗ - 失败
  * ⚠️ - 警告/需要更新
  * 🔍 - 检查中
  * 🔄 - 更新中

### 6.3 表格格式
- **约束：** MUST 使用固定宽度 printf 格式
- **列宽：**
  * 工具名：20 字符
  * 当前版本：12 字符
  * 最新版本：12 字符
  * 状态：15 字符
- **表头：** `printf "%-20s %-12s %-12s %-15s\n" "工具名" "当前版本" "最新版本" "状态"`
- **数据行：** `printf "%-20s %-12s %-12s %-15s\n" "$tool" "$current" "$latest" "$status"`

### 6.4 状态值
- `"✓ 最新"` - 当前版本 == 最新版本
- `"⚠️ 需要更新"` - 当前版本 != 最新版本
- `"✗ 未安装"` - 工具未安装
- `"✗ 检查失败"` - 网络或解析错误

## 7. 错误处理约束

### 7.1 错误消息格式
- **约束：** MUST 使用结构化格式
- **格式：** `[ERROR] tool=<工具名> action=<check|update> reason=<错误描述>`
- **示例：** `[ERROR] tool=@openai/codex action=check reason=网络请求失败`
- **致命错误：** `[ERROR] <错误描述>`（无 tool 和 action 字段）

### 7.2 输出流
- **约束：** 所有错误 MUST 输出到 stderr
- **约束：** 所有正常输出到 stdout

### 7.3 错误策略
- **约束：** fail-soft（继续执行）
- **实现：** 一个工具失败不阻止其他工具更新

## 8. 退出码约束

### 8.1 退出码定义
- **0：** 正常执行完成（即使部分工具更新失败）
- **1：** 致命错误（Volta 未安装或检测到并发实例）

### 8.2 非致命错误
- **约束：** 以下错误不影响退出码（仍返回 0）
  * 网络请求失败
  * JSON 解析失败
  * volta install 失败
  * 工具未安装

## 9. .command 文件约束

### 9.1 实现方式
- **约束：** MUST 创建独立的 .command 文件
- **内容：** 与 .sh 文件相同，但在末尾添加暂停代码
- **暂停代码：**
  ```bash
  echo ""
  read -p "按任意键关闭..." -n1
  ```

### 9.2 权限
- **约束：** MUST 设置可执行权限
- **命令：** `chmod +x update-volta-tools.command`

## 10. 并发执行约束

### 10.1 检测策略
- **约束：** MUST 使用进程检测防止并发
- **实现：** `pgrep -f "update-volta-tools" | grep -v $$`
- **行为：** 如果检测到其他实例，输出错误并退出（退出码 1）

## 11. 环境检查约束

### 11.1 必需检查
- **Volta 安装：** `command -v volta >/dev/null 2>&1`
- **并发实例：** `pgrep -f "update-volta-tools" | grep -v $$`

### 11.2 不检查
- **curl：** 假设 macOS 默认包含
- **Bash 版本：** 假设 macOS 默认 Bash >= 3.2

### 11.3 致命错误
- **Volta 未安装：** 输出 `[ERROR] Volta 未安装，请先安装 Volta` 到 stderr，退出码 1
- **并发实例：** 输出 `[ERROR] 检测到其他实例正在运行，请稍后再试` 到 stderr，退出码 1

## 12. 更新流程约束

### 12.1 更新命令
- **约束：** MUST 使用 `volta install <package>@latest`
- **示例：** `volta install @openai/codex@latest`

### 12.2 更新顺序
- **约束：** MUST 按顺序更新，不并行执行
- **理由：** 避免 Volta 冲突

### 12.3 更新条件
- **约束：** MUST 满足以下条件才执行更新
  * `I(p) ≠ ⊥`（当前版本已知）
  * `L(p) ≠ ⊥`（最新版本已知）
  * `I(p) != L(p)`（版本不等）

### 12.4 用户确认
- **约束：** 不需要用户确认，自动执行所有更新

## 13. 工具列表约束

### 13.1 硬编码工具
- **约束：** MUST 硬编码以下三个工具
  1. `@openai/codex`（显示名：codex）
  2. `@anthropic-ai/claude-code`（显示名：claude-code）
  3. `opencode-ai`（显示名：opencode）

### 13.2 不支持配置
- **约束：** 不提供配置文件来自定义工具列表
- **理由：** 需求明确，配置文件增加复杂度

## 14. 摘要输出约束

### 14.1 摘要格式
```
========================================
更新完成！
成功：<count> 个工具
失败：<count> 个工具
跳过：<count> 个工具
========================================
```

### 14.2 失败工具列表
- **约束：** 如果有失败的工具，MUST 列出失败工具名称

## 15. Property-Based Testing 约束

### 15.1 必须验证的不变量
1. **幂等性：** 运行脚本两次，第二次不产生任何 volta install 调用
2. **包隔离性：** 一个包的失败不影响其他包
3. **Fail-soft：** 非致命错误输出到 stderr，脚本继续执行
4. **网络边界：** 每个包最多 3 次 curl 调用
5. **退出码边界：** 仅 0 或 1，非致命错误不改变退出码
6. **非交互：** 脚本从不读取 stdin（.command 除外）

### 15.2 反例生成策略
- JSON 变体：额外空格、换行符、嵌套字段、转义引号
- 版本变体：前导零、v 前缀、语义等价但文本不同
- 错误注入：curl 失败、volta install 失败、解析失败
- 边界测试：超长字符串、CJK 字符、emoji、控制字符
